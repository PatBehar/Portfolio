01 / BUSINESS CONTEXT

Keep agent-like actions grounded and approved

Support operations · fictional case

A high-priority support case needs review against a written escalation policy. The workflow should show where its recommendation came from and hold any write until a person explicitly approves it.

Synthetic case fixture CASE-2417; no customer system or external service is connected.

  • Untrusted case notes

    Free-text notes can contain irrelevant or malicious instructions.

  • Untraceable advice

    A recommendation without source records is difficult to verify.

  • Unapproved side effects

    A write action must require an explicit, enforced human decision.

02 / PROCESS DESIGN

Original process and architecture diagrams

The source diagram file contains the original AS-IS, TO-BE and Architecture pages. The running workflow uses a local MCP client and independent stdio server process.

03 / IMPLEMENTED FLOW

Real tool calls, deterministic planning, human approval

FastAPI starts an independent local MCP stdio child process, negotiates the protocol and calls the allowlisted read tools before producing a deterministic proposal.

  1. 01

    Investigate

    Call get_case and get_escalation_policy through the real local MCP protocol.

  2. 02

    Ground the proposal

    Apply explicit case priority and age rules; cite the retrieved case and policy records.

  3. 03

    Require a decision

    A person may approve or deny the proposed follow-up.

  4. 04

    Enforce the write

    Approval binds a short-lived, one-use grant to the exact proposal and case version.

Approval and reliability controls

  • The write tool rejects missing, expired, altered, replayed or mismatched approval grants.
  • Approval creates one local SQLite follow-up; an identical approval replay is idempotent.
  • Case notes are treated as untrusted input and excluded from deterministic planning.

FastAPI + independent MCP stdio server + local SQLite · no LLM planning, CRM, ticketing, cloud or paid API.

04 / TECHNICAL CHOICE

Tools provide facts; rules select the action

The prototype uses real MCP discovery and typed tool results, but the planner is deterministic. This keeps the recommendation inspectable and makes human approval a server-enforced boundary.

No autonomous agent planning or external model call is demonstrated.

Prototype stack

  • Python 3.12
  • FastAPI
  • Official MCP Python SDK
  • stdio / JSON-RPC protocol
  • Rule-based planner
  • SQLite
  • Local HTML / CSS / JavaScript
