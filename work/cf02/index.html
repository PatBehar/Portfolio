01 / BUSINESS CONTEXT

Make request data easier to verify

Northstar Services · fictional scenario

Northstar Services is a fictional company, and the request examples are synthetic. One sample arrives as free-form text asking to reissue an invoice. An Operations specialist reads it, copies the account, contact, request type, and requested action into a case, then follows up for missing details and updates a manual register. This prototype explores how to capture only what the text supports and route uncertain fields to review.

Fictional scenario and synthetic request text; this prototype does not process uploaded files.

  • Missing details

    Required fields may be absent or unclear in a short request.

  • Unverifiable values

    A candidate value should be tied to the words that support it.

  • False confidence

    Uncertain or conflicting results need a clear human review route.

03 / IMPLEMENTED FLOW

Deterministic extraction with a review path

The local FastAPI application reads synthetic request text, extracts labeled values and explicit request cues, validates a strict schema and checks each populated field against source evidence.

  1. 01

    Choose a fixture

    Load one of the fictional request examples bundled with the demo.

  2. 02

    Extract fields

    Compare deterministic rules with a separately labeled MOCK fixture response.

  3. 03

    Check evidence

    Validate required fields, source text and the 0.85 ready threshold.

  4. 04

    Review & audit

    Approve or request more information; the audit stores metadata and a request fingerprint.

Scope and safeguards

  • The MOCK returns a bundled candidate only for the exact fixture ID and request text; it makes no model call.
  • Uncertain values remain null or route to human review; uploaded files, OCR and PDF parsing are not implemented.
  • Request text is not persisted; the audit stores a SHA-256 fingerprint and trace metadata.

One local FastAPI app and SQLite store · synthetic text only · no external case-system write.

04 / TECHNICAL CHOICE

Evidence before inference

Labeled fields and explicit cues make the rule path testable. The comparison path is intentionally bounded to known fixtures; ambiguous inputs are presented for human review instead of being guessed.

The MOCK label is literal: this demo makes no LLM or external inference call.

Prototype stack

  • Python 3.12
  • FastAPI
  • Pydantic
  • Deterministic rules
  • SQLite
  • REST / JSON
  • Local HTML / CSS / JavaScript
