01 / BUSINESS CONTEXT

Trace operational signals back to source rows

Customer support · synthetic operating model

All records in this example are synthetic and generated from a fixed seed. An Operations lead wants to compare two fictional support teams over equivalent periods and understand the data behind SLA performance, first-contact resolution, handling time, backlog, and volume. In this scenario’s current reporting flow, analysts assemble exports, calculate KPIs, and trace unusual signals back to cases before choosing what to investigate. This prototype makes the definitions and source records inspectable; a threshold is a review cue, not proof of cause.

Seed 60114 contains fictional records for a fixed synthetic reporting window; it is not actual service performance.

  • Aggregates without lineage

    A KPI should be traceable to the underlying source records.

  • Misleading denominators

    Eligibility and maturity rules change what a metric means.

  • Signals mistaken for causes

    A threshold breach is a review cue, not proof of root cause.

02 / PROCESS DESIGN

Original process and architecture diagrams

The diagrams document a manual reporting baseline, proposed metrics analysis and the local data path. The dashboard reads seeded synthetic records through SQL-backed endpoints.

03 / IMPLEMENTED FLOW

SQL-backed KPIs with evidence you can inspect

The local application loads a reproducible synthetic dataset into SQLite and computes service metrics through explicit SQL and deterministic anomaly rules.

  1. 01

    Load synthetic records

    Use the tracked dataset and manifest; no generator rewrites source files during the demo.

  2. 02

    Filter the view

    Select a team and reporting period in the local dashboard.

  3. 03

    Review the metrics

    Inspect SLA, FCR, AHT, backlog, volume and weekly trends under their defined contracts.

  4. 04

    Trace a signal

    Open source rows supporting a threshold-based anomaly and review recommendation.

Metric interpretation

  • The KPI definitions declare eligibility, maturity and denominator rules.
  • Anomaly rules are deterministic and cite evidence IDs; they do not establish causation.
  • The dashboard is read-only and does not trigger operational actions.

Local FastAPI + SQLite · 540 synthetic cases and seeded event tables · no LLM or external service.

04 / TECHNICAL CHOICE

Defined metrics before narrative

Explicit SQL contracts make filters, denominators and source rows inspectable. Deterministic threshold rules surface review signals while keeping root-cause interpretation with an analyst.

The dataset is synthetic, fixed and reproducible; the displayed KPIs are not real business results.

Prototype stack

  • Python 3.12
  • FastAPI
  • SQLite
  • SQL metric contracts
  • Deterministic thresholds
  • Seeded CSV dataset
  • Read-only HTML / CSS / JavaScript dashboard
