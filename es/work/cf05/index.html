01 / CONTEXTO DE NEGOCIO

Mantener las acciones fundamentadas y sujetas a aprobación

Operaciones de soporte · caso ficticio

Un caso de soporte prioritario necesita revisarse frente a una política de escalamiento. El flujo debe mostrar de dónde proviene la recomendación y detener cualquier escritura hasta recibir aprobación explícita.

Fixture sintético CASE-2417; no se conecta ningún sistema externo ni de clientes.

  • Notas no confiables

    El texto libre puede incluir instrucciones irrelevantes o maliciosas.

  • Recomendaciones sin trazabilidad

    Una acción sin fuentes es difícil de verificar.

  • Efectos sin aprobación

    La escritura requiere una decisión humana aplicada en el servidor.

02 / DISEÑO DEL PROCESO

Diagramas originales de proceso y arquitectura

El archivo fuente contiene las páginas originales AS-IS, TO-BE y Arquitectura. El flujo funcional usa un cliente MCP local y un servidor de proceso stdio independiente.

03 / FLUJO IMPLEMENTADO

Llamadas de herramientas reales, reglas y aprobación humana

FastAPI inicia un proceso hijo MCP independiente por stdio, negocia el protocolo y llama las herramientas de lectura permitidas antes de generar una propuesta determinística.

  1. 01

    Investigar

    Consultar get_case y get_escalation_policy mediante el protocolo MCP local real.

  2. 02

    Fundamentar la propuesta

    Aplicar reglas explícitas de prioridad y antigüedad; citar caso y política.

  3. 03

    Exigir una decisión

    Una persona puede aprobar o denegar el seguimiento propuesto.

  4. 04

    Aplicar la escritura

    La aprobación vincula un permiso de un uso y corta duración a la propuesta y versión exactas del caso.

Controles de aprobación y confiabilidad

  • La herramienta de escritura rechaza permisos faltantes, vencidos, alterados, repetidos o no coincidentes.
  • La aprobación crea un seguimiento en SQLite local; repetirla de forma idéntica es idempotente.
  • Las notas del caso se tratan como entrada no confiable y no participan en la decisión determinística.

FastAPI + servidor MCP independiente por stdio + SQLite local · sin planificación LLM, CRM, tickets, nube ni API pagada.

04 / DECISIÓN TÉCNICA

Las herramientas aportan datos; las reglas eligen la acción

El prototipo usa descubrimiento MCP real y resultados tipados, pero el planificador es determinístico. Así la recomendación es inspeccionable y la aprobación humana constituye un control aplicado en el servidor.

No se demuestra planificación autónoma de agentes ni llamadas a modelos externos.

Stack del prototipo

  • Python 3.12
  • FastAPI
  • SDK oficial de MCP para Python
  • stdio / protocolo JSON-RPC
  • Planificador basado en reglas
  • SQLite
  • HTML / CSS / JavaScript local

Observado en este recorrido local

  • Descubrimiento MCP y lectura del caso y política, seguidos por una propuesta con fuentes.
  • Una aprobación explícita, una escritura local de seguimiento y un evento de auditoría.

Límites del prototipo

  • Fixtures y políticas ficticias; sin CRM, tickets ni efectos externos.
  • Planificación con reglas; sin LLM ni decisiones autónomas.
  • Sin evidencia de resultados de negocio, mejora de servicio o seguridad productiva.
